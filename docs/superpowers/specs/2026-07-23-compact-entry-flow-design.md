# 主查詢與句格工作台緊湊詞條流設計

## 目標

統一主查詢與句格工作台的詞條框排版。詞條框邊界緊貼字面，不再由固定網格平均拉寬；在一般 375px 手機寬度下，2–5 字詞每行不得少於 4 個，短詞能容納更多便容納更多。相同規則同時適用窄屏與寬屏。

本改動只涉及詞條呈現，不改候選排序、分頁、POS、查詢或資料契約。

## 呈現契約

### 共用詞條流

- 主查詢與工作台共用一套內容寬度詞條流。
- 容器由左至右緊密排列並自然換行；剩餘空間留在行尾，最後一行同樣靠左。
- 詞條框不平均拉伸、不置中整行，也不依字數跨固定欄。
- 框寬由字面主導，水平 padding 為 `4px`，詞條間距為 `6px`。
- 每個框維持至少 `44px × 44px` 的可點擊範圍。

### 字面縮放

- `short`（1–3 字）：`16px`。
- `medium`（4 字）：`14px`。
- `long`（5 字）：`12px`。
- `overflow`（6 字以上）：`12px`，不再隨長度持續縮小。

正常詞條保持單行，整個詞條框換到下一行。只有單一詞條本身寬過可用容器時，才允許框內斷行；不得造成水平溢出。

### 主查詢

- 詞條框只顯示字面。
- 移除現有 5–6／7–8／9 字以上的網格跨欄規則。
- 移除依 `em` 計算的最小網格欄寬，避免實體手機文字縮放改變每行數量。

### 句格工作台

- 詞條框第一行顯示字面。
- 第二行顯示較小的等寬碼；碼不得撐寬詞條框。
- 粵拼與命中原因不再於詞條框常駐顯示，保留在點擊後的候選詳情。
- 候選資料不刪減，候選詳情與套用流程維持原契約。
- 移除 `candidate-card--wide` 與固定 `6.5rem`／`9.5rem` 最小欄寬。

## 實作邊界

- 建立共用字面長度分級 helper，只輸出 `short`、`medium`、`long`、`overflow` 四類。
- 不以 JavaScript 量度字型像素，也不以 JavaScript 計算每行數量。
- 主查詢與工作台輸出共用 flow／chip class；兩個元件只保留內容差異。
- CSS 使用內容寬度、`flex-wrap` 與左對齊完成排版。
- 寬屏與窄屏共用同一排版邏輯，不另設固定欄數版本。

## 驗收

1. 在實際瀏覽器 375px viewport 中，2、3、4、5 字詞各自連續出現時，每行均至少顯示 4 個。
2. 2–3 字短詞在空間許可時可多於 4 個。
3. 主查詢與句格工作台的框寬都緊貼字面，不平均填滿整行。
4. 最後一行靠左，不置中、不分散對齊。
5. 6 字以上詞條不受固定每行數量限制，優先整框換行。
6. 單一超寬詞條不造成水平捲動。
7. 工作台詞條框只顯示字面與碼；點擊後詳情仍可查看粵拼、碼與命中原因。
8. 寬屏與窄屏使用同一詞條流規則。
9. 主查詢、工作台候選排序、分頁、POS 與套用行為不變。
10. 前端 lint、production build、既有 smoke tests 與新增版面回歸全部通過。

## 不做

- 不改候選內容、排序或載入數量。
- 不把工作台粵拼或命中原因從候選資料移除。
- 不引入 JavaScript masonry、ResizeObserver 排版或逐框像素量測。
- 不為長詞硬性指定每行數量。
