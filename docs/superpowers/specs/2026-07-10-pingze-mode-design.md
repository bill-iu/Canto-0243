# 平仄模式設計

日期：2026-07-10
狀態：已獲產品設計核准，待實作計劃

## 目標

將平仄搜尋由全域、會與粵拼 `p`／`z` 聲母衝突的自動辨識，改為獨立的**平仄模式**。此模式可自由選擇 `0243`、`02493`、`394052` 三個 sub-mode；`P`／`Z` 始終按 394052 判斷，而數字 slot 則完全沿用所選 sub-mode 的既有純碼等價規則。

平仄模式須可與既有串列、單位通配碼、字面錨、韻錨和缺字型查詢組合；不支援粵拼錨。

## 非目標

- 不改變 0243、02493、394052、近反義模式的既有查詢語義。
- 不在一般模式內自動辨識、轉檔或提示平仄查詢。
- 不重寫現有排序、去重、分頁或詞庫碼資料。
- 不讓平仄模式支援粵拼錨，避免 `p`／`z` 字母重回歧義邊界。

## 使用者介面與狀態

頂欄新增「平仄模式」，與三個既有 0243 家族模式及近反義模式並列。選入平仄模式後，顯示 `0243（鬆）`、`02493（緊）`、`394052（六聲）` 三個 sub-mode 控制項。

首次進入平仄模式時，sub-mode 取目前／最近使用的 0243 家族模式；其後切換平仄 sub-mode 只改變數字 slot 的比對規則，不改變 `P`／`Z`。每個搜尋 tab、瀏覽器歷史項目與分享 URL 均保存 mode 與 sub-mode。URL 使用 `mode=pz` 表示平仄模式，並以 `pzmode=m1|m2|m3` 保存 sub-mode；沒有 `pzmode` 的舊／手寫連結預設為 `m1`。

離開平仄模式後，輸入不再帶有任何平仄特殊含義，沒有自動切換。`p`、`z`、`pa`、`zoeng` 等輸入按既有粵拼片段流程處理。

## 查詢語法

平仄模式只新增兩個單位 slot：

| Token | 每位條件 |
|---|---|
| `P` | 該位 394052 碼為 `0` 或 `3` |
| `Z` | 該位 394052 碼不是 `0` 或 `3` |
| 數字 | 該位按目前 sub-mode 的既有純碼規則比對 |
| `?` | 剛好一位，不設字面、聲調或音韻條件 |

`?` 不匹配任意長度，也不是漢字文字查詢。`PZ?` 與 `?PZ` 均為三位逐位模式；`PZ3` 的第三位是依 sub-mode 比對的數字 slot。

平仄 slot 可以放在既有串列／通配碼語法容許的任何位置，並與既有錨語法合成。例如：

- `PZ好=`：前兩位分別為平、仄；`好=` 仍是既有韻錨，不是固定字面 slot。
- `?PZ好=`：前三位為逐位條件，尾部仍套用既有 `好=` 韻錨。

現有純漢字查詢與不含平仄 token 的既有合法語法，在平仄模式下維持原有行為。粵拼錨在平仄模式中必須拒絕，並提示「平仄模式不支援粵拼錨，請切換 0243 搜尋模式」。平仄模式中其他無法組成既有合法語法的輸入，提供平仄模式專屬的語法提示；不靜默回落為粵拼。

## 架構

新增 `pingze` UI／URL mode，並在搜尋 context 內保留獨立 `pingzeSubMode`。底層執行模式不是以單一 `m3` 取代 context：碼位 matcher 必須同時取得平仄判定需要的 394052 碼與數字 slot 需要的 sub-mode 規則。

解析入口改為 mode-aware：

1. 一般模式維持現有 parser，完全不呼叫平仄 parser。
2. 平仄模式先解析既有外層語法，再把其中可作逐位碼條件的 `P`、`Z`、數字與 `?` 編譯為同一個 `MatchSpec`。
3. `MatchSpec` 新增平仄 slot constraint；數字 slot 重用現有 mode-aware code constraint；韻錨、字面錨和其他既有 slot 維持既有 constraint。
4. 現有 position matcher 執行合成後的 spec，沿用候選取得、排序、去重與分頁。

不得為每種既有語法建立獨立平仄 executor，也不得先把 `P`／`Z` 展開成多個數字查詢後合併結果。前者會造成語法分支漂移；後者無法正確保留 sub-mode、錨、排序和分頁語義。

Python 服務端與 TypeScript／PWA port 均實作相同的 mode-aware parser、slot model 與 matcher 契約。共享模式偵測、URL state 與 query-kind／match-spec registry 需要一併擴充；生成檔只由既有 generator 更新，不手動漂移。

## 錯誤處理與相容性

- 舊有 `PZ`／`ZP` 自動切換 394052 的行為移除。
- 一般模式中的 `P`／`Z` 不再產生平仄「只接受 P、Z、數字」錯誤。
- 平仄模式保留明確的語法錯誤與不支援粵拼錨提示。
- 既有非平仄 URL、tab state 及 API call 不帶 `pzmode` 時保持可用。

## 驗收測試

### 模式隔離

- 一般模式中的 `p`、`z`、`pa`、`zoeng` 走粵拼片段路徑。
- 一般模式的 `PZ` 不自動轉平仄模式。
- 平仄 token 只在 `mode=pz` 被辨識。

### Slot 及 sub-mode

- `P`／`Z` 對每個 394052 碼位的分類正確。
- 每一個 sub-mode 下，平仄模式數字 slot 的候選集合與同位置純碼查詢的等價規則一致。
- `?` 僅放寬一個位置，並正確處理前置、中置、尾置。

### 組合文法

- 覆蓋 `PZ?`、`?PZ`、`PZ3`、`PZ好=`、`?PZ好=`，以及現有允許的字面錨、韻錨、缺字型組合。
- 平仄模式中的粵拼錨回傳指定提示。
- 非法平仄組合回傳平仄專屬語法提示。

### 端到端與 parity

- UI mode、sub-mode、tab restore、瀏覽器返回與 `mode=pz&pzmode=…` URL round-trip 正確。
- Python 與 TypeScript parser、matcher、mode-detect 的契約案例一致。
- 搜尋結果的排序、去重、分頁與既有 position match 無回歸。
