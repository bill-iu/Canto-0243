定位：寫作聯想、「論文降重」同義詞替換。結果名義上含近義、反義、同義。

### 2.2 `/cidian` 文案

> 漢語詞典收錄了近**50 萬**個詞語……

### 2.3 `/about`（合規關鍵）

1. 「網站數據**主要來源於互聯網**……大量編輯和整理，**若有侵權，請聯系我們刪除**。」  
2. 「**歡迎**鏈接和**采集**本網站數據」，但 **QPS ≤ 2**。  
3. 相似詞接口：`https://kmcha.com/api/similar/xxx`，**最大 QPS 為 5**。  
4. 聯絡：`nihaoma0811@gmail.com`

→ 站方自承資料來自互聯網彙編＋侵權申訴管道；**未**附 CC／MIT／開源辭典授權檔；「歡迎采集」是**使用政策／限速**，不是著作權轉授。

### 2.4 `robots.txt` 張力

```
Disallow: /about
Disallow: /api
…
```

關於頁鼓勵 API／采集，但 robots 對通用爬蟲 **Disallow `/api`**。生產合規應以 about＋著作權法為準，不能假設「可任意鏡像再分發」。

## 3. Technical provenance（服務指紋）

實測（2026-07-14）顯示 **至少三層異質資料**，不要把「相似詞查詢」當成單一詞林。

### 3.1 Layer A — API「相似詞」（語料／共現風格）

請求：`GET /api/similar/开心`  

回應形狀：

```json
{"word":"开心","similar":["高兴","很开心","开心啊","不开心","开心吧","我们开心","难过",…]}
```

特徵：

- 大量**短語／搭配**（「很開心」「開心啊」「我們開心」），而非經典反義詞典單字對。  
- 與結果頁 HTML 區塊「開心的**相似詞**」**逐條一致**（抽樣「開心」：API 30 詞＝HTML 相似詞 30 詞）。  
- 此層對應站方「全網數據挖掘／機器學習」敘事；**不是**同義詞詞林葉組圖。

### 3.2 Layer B — HTML「近義詞／反義詞」（辭典型列表）

結果頁另有：

- `#synonyms`「…的近義詞」  
- `#antonyms`「…的反義詞」

「開心」抽樣近義含 **怡悅、忻悦、夷愉** 等書面語／罕用詞；反義含惱恨、悲戚、凄滄等——體裁屬**教學站互相鏡像的近反義表**，與 Layer A 明顯不同。

與教育站交叉指紋（同日）：

| 對照 | 觀察 |
|------|------|
| 學習力 xuexili「開心」反義列表 | 與 kmcha HTML 反義 **Jaccard ≈ 0.72**（高度同源循環內容） |
| 古詩句／多站「開心近義」列表 | 同樣出現怡悅／忻悦／夷愉等標識詞 |
| 本庫 cilin（`data/cilin/new_cilin.txt`） | 「開心」無鄰接命中；「黑暗」「痛苦」僅部分詞重疊——**不足以證明主源是詞林** |
| 本庫 guotong（`dict_antonym.txt`，繁體 `A——B`） | 格式／腳本皆異；非同一交付物 |

### 3.3 Layer C — 「基本釋義」（辭典釋義體）

「開心」釋義觀測：

> 1.（形容詞）心情快樂舒暢：開心得很 \| 十分開心。［反義詞］痛苦。  
> 2.（動詞）戲弄別人，使自己高興：拿別人開心。

同文高度出現於：

- kmcha `/cidian/开心`（同源站內）  
- 漢辭寶等網路詞典（體例為（形）…［反］痛苦；幾乎同句）  
- 百度漢語等 KG／詞典結果（「開心」反義上下文出現同樣釋義句）

體例標記（詞類括註、［近義詞］／［反義詞］、用例用 `|`）是典型**《現代漢語詞典》系／在線漢語詞典鏡像**風格。  

**注意**：商務印書館《新華字典》主體是**字頭**字典；詞條級帶（形容詞）＋複合詞例句的釋義，市場行銷常笼统叫「新華」，技術上**更像現漢／彙編詞典 dump**，而非可核對 ISBN 的單一千淨來源。站方「最新版新華字典」主張**缺乏版本號、書目或官方 API 背書**。

釋義內嵌之［反義詞］通常是 HTML 反義列表的**子集**（例如開心 → 痛苦），列表本身更長、來源可能另表。

## 5. License & fit to Canto-0243（授權與適配）

### 5.1 再分發風險

| 面向 | 判定 |
|------|------|
| 站方開源授權 | **無** |
| 「歡迎采集」 | 限速下的**瀏覽／查詢便利**，不構成對《現漢》／彙編著作的轉許可 |
| 侵權申訴句 | 自承可能含侵權內容 → 下游再打包風險高 |
| 《新華》《現漢》類正文 | 商務印書館等**專有**；商用／開源嵌入通常需正式授權 |
| 網路教輔近反義表 | 著作權混雜、來源不可追溯；「大家網站都有」≠ public domain |
| 共現相似詞 | 即使用產出物，鏡像全表仍缺清晰授權；且品質＝搭配而非直連反義 |

對照 `CONTEXT.md`：**授權閘：只納可再分發者**；反義主路徑 guotong，**唔 OpenHowNet**。kmcha 比 OpenHowNet 更不透明（多源混合物＋侵權免责話術）。

### 5.2 產品適配

- 簡體為主；共現層含大量非詞條短語，與粵語詞庫字面 membership 衝突大。  
- API 層混入「難過」當「開心」相似鄰居（相關而非反義／近義嚴格區分），不宜當直連 `ant` 權威。  
- HTML 反義列表較像教輔枚舉，仍無清晰授權鏈。

## 6. Verdict（裁決）

### **no**（不可作為 Canto-0243 低風險近／反義匯入源）

理由收束：

1. **來源不純**：至少「共現相似／教輔近反義表／詞典釋義」三層；無法釘單一可再分發上游。  
2. **授權不合格**：無開源條款；「歡迎采集」≠ redistributable license；自帶侵權刪除管道。  
3. **價值不足**：品質上不如已有 guotong＋project_ant＋（條件式）MOE 相反詞欄；共現層還会污染直連反義語意。  
4. **YAGNI**：為不明彙編再寫 NOTICE／過濾管線，不如維持既有閘。

### 什麼時候才接近「可引用」

僅作**人工靈感**（人工核對後寫入 `project_ant`），且遵守站方 QPS；**不得**把 API／HTML 批量鏡進靜態詞林埠或冒充專案自建權威。
