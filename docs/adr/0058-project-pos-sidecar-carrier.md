# ADR-0058: 專案自建詞性以獨立詞性載體交付

領域詞彙：見 [CONTEXT.md](../../CONTEXT.md) § 詞性與分類（**專案自建詞性**、**專案自建詞性清單**、**詞性載體**）。

## 決策

1. **專案自建詞性** 嘅 git 權威係 **專案自建詞性清單**；runtime（Portable／PWA／campaign 工具）讀 **詞性載體**，**唔**把詞性權威寫入 **詞條庫** 主檔欄位再經 **詞條從源重建** 先生效。
2. **詞性載體** 有獨立完整性／版本標識；可喺**唔**做 **詞庫版本 bump** 下更新。與詞庫版本允許短期漂移。
3. 載體未就緒或缺失時回退 **詞性缺標** 行為；**唔**阻塞 **就緒閘解鎖**。
4. 創作者只讀詞性；提案須經 **詞性提案審核** 先入清單。

## 理由

曾考慮建庫套入 DB（同反義清單文化一致）。選獨立載體，係為詞性標註迭代快過詞庫發佈節奏：campaign／面板標籤可單獨換版，唔逼每次改標都重烘焙 `lyrics.db`。代價係多一個 payload、渠道要各自掛載同版本校驗，並明確容忍與詞庫漂移。

## 後果

- PWA／Portable 須有載體掛載與快取淘汰路徑（細節實作訂）。
- 查詢與工作台須在無載體時仍可搜尋；同桶過濾變 no-op（缺標契約）。
- 若日後證明漂移成本過高，可另 ADR 改回建庫套入；唔默默雙寫兩套權威。
