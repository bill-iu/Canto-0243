# ADR-0069: 句格工作台替換段寬＝句長（取消 4 格硬頂）

**替換段** 早期硬限寬度 1–4（鎖點 bounding span 超寬即 `span_too_wide`）。創作者需要一次標定更長連續段（成語／長句局部），同時唔想改「一字面＝全段」候選模型，亦唔想真·無限長度過過起句上限。

## 決策

1. **段寬上限＝當句字位數**（與**工作台起句**相同；現行 **64**）。取消「最多連續四格」硬拒；鎖點只要落在句內即可形成替換段。
2. **候選模型不變**：一次候選仍係**一個等長字面**套用成段；允許多詞拼段／自動切段 **唔**在本決策範圍。空池可接受。
3. **同韻／同聲位點 UI**：`width ≤ 6` 維持整段／頭／尾／中間位勾選；`width ≥ 7` 只保留整段／頭／尾（中間位靠「整段」覆蓋）。
4. **空池輕提示（可見候選 = 0 先出）**  
   - 段寬 **5–20**：詞庫呢個長度較少；可改條件、縮段或**段手打**。  
   - 段寬 **≥ 21**：現庫無等長詞結構空間；引導縮段／段手打，**唔**暗示再放寬就會有詞。  
   文案講「目前詞庫」，**唔**把 20 寫成永久產品承諾。
5. **查詢捷徑**：段寬 **> 20** 時**跳過**候選查詢（即空＋≥21 文案）。常數 `WORKBENCH_LEXICON_MAX_WORD_LEN = 20` 對齊現庫觀測最長字面（1 條 20 字）；**獨立於**關係收錄 `MAX_WORD_LEN = 12`。換庫若出現更長詞，先調常數；可選日後改為開庫讀 `max(length)`。
6. **契約上限**：plan `width`、candidate `literal`、`semanticSeed`、放寬 `positions` 等與段寬相關之硬頂改跟 **句長（64）**，唔再 `le=4`。
7. **雙通道**：PWA（TS）與 Desktop／Portable（Python schema + planner）同一契約。

## 理由

- 「無限制」喺產品上＝唔再被 4 格綁死，而係跟已有一句 64 格模型。
- 現庫 `words.char` 最長 20；≥21 必無等長候選，照打 SQLite 無增值。
- 短段（≤6）仍要中位押韻精度；闊段 checkbox 會炸 UI。
- 多詞拼段係另一功能，捆綁會膨脹範圍。

## Considered

| 選項 | 結果 |
|------|------|
| 段寬跟 `MAX_WORD_LEN`（12）或觀測 20 | 拒作段寬硬頂（碼／通配／段手打仍可能要更長段） |
| 真無限（>64） | 拒；要重開起句／storage |
| 闊段多詞拼段／自動切段 | 拒（另案） |
| 闊段只准手改、唔出候選區 | 拒（半殘體驗） |
| 闊段 phoneme 列出全部中位 | 拒（UI／a11y） |
| 一律簡化 phoneme 只頭尾 | 拒（削弱 2–6 格精度） |
| 開庫動態 `max(length)` 做 skip | 延期；第一期常數 20 |
| 空池唔分級文案 | 拒；≥21 同「較少」語意不同 |

## Consequences

- 改 `replacement-span`／`line-draft`／`contracts`／`line-draft-storage`；Python `workbench_schema` 同步；self-check 由「>4 拒」改為「≤句長可鎖」。
- UI：去掉「一次最多改連續四格」；空態兩級 copy；`width>20` 短路徑。
- CONTEXT：**替換段** 定義更新；舊 design doc 1–4 作歷史。
- `ponytail:` skip 常數 → 可升動態 max length。
